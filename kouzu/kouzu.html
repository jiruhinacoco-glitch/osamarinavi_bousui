納まりナビ 全体の構図（案）

2026-11-23　いただいた図（客先登録・仕様登録・材料登録）を土台に、現場の流れまで入れて組み直した案です。画面の並びではなく、「どのデータを・どこに1つだけ持つか」の図です。

考え方は3つです。① 配るデータと自社のデータを分ける。② 同じことは1か所にだけ持ち、ほかからは「指す」。③ 登録は、現場の流れ（数量 → 見積 → 発注 → 請求）に数字を流すためにある。

線はすべて たて・よこ だけです。帯をまたぐつながり（青）は、同じ列の真上・真下に通してあります。図は横に長いので、せまい画面では横に送って見てください。

いただいた図から変えた所と、その理由

項目いただいた図この案理由
材料の値段材料登録の中に「価格」が1つ「仕入単価」という別の箱（材料×商社）。標準の印を1つ商社Aと商社Bで値段が違う。材料の行を増やさずに、何社ぶんでも持てる。発注は選んだ商社の値段、見積は標準の値段
塗布量・使用量材料登録の中工程の中（仕様ごと）。材料には「カタログの標準量」を参考として残すだけ同じ材料でも仕様によって量が違う（GO-JIN V が 1.3 と 2.0 など）。材料に1つだけ持つと合わない
1㎡あたりの係数・有効㎡材料登録の中自社の工程の中（マイ仕様）。ラップ・ロスは会社と仕様で変わる材料の性質（1巻＝16㎡）と、使い方の係数（重ね・ロス）を分ける
工程と材料のつなぎ方名前の文字が合うかで探す材料の番号で指すいまは「GO-JIN 500／50」と「GO-JIN500」のように字が1つ違うと切れる。今日も何度もこれで外れた
どれか1つ選ぶ材料「ポリマリットフェース または ポリマリット35」と文で書く工程に「選べる組」として持つ文のままだと数量も金額も出せない。保護塗料の4択・断熱材の2択が多い
平場と立上り仕様番号の下に工程が1列仕様番号の下に「部位ごとの層」（平場・立上り・役物まわり）1つの番号に平場と立上りの2つの工程表がある。別の仕様として並べると一覧が倍になる
メーカーの仕様と自社の仕様仕様登録に1つ①参考データ（配る・読むだけ）と ②マイ仕様（取り込んで直せる）配るデータと、会社が直したデータを混ぜないため。カタログが改訂されたら、取り込み元の版と比べて知らせられる
確認の状態無い仕様と材料に「読取 → 確認済 → メーカー公認」一次情報をどこまで確かめたかを、ページ数を見せずに示せる
取引先の種別元請・協力業者・商社・メーカーのどれか1つ1社に複数の印商社でありメーカーの代理店、元請であり協力業者、という会社がある
拠点・担当者企業の中に1つずつ別の箱（1社に複数）支店ごとに住所と担当が違う。発注書・見積書の宛先はここから選ぶ
締め日・支払い条件企業の中「取引の条件」（相手との取引に付く）元請として売るときと、商社として買うときで条件が違う
現場の流れ図に無い③ 物件 → 屋根 → 部位 → 数量 → 見積 → 発注 → 記録 → 請求登録（①②）は、この流れに数字を流すためにある。ここまで1枚に入れて初めて、何をどこに持つべきかが決まる
実績を戻す道無い実績（実際に使った量）→ マイ仕様の量を直す見積と実際の差が、次の見積を正確にする。会社ごとの財産になる所

3つの帯の役割

  • ① 参考データ：メーカー → 製品 → 仕様 → 部位ごとの層 → 工程 → カタログの材料。いただいた図の「仕様登録」の木（メーカー → 製品名 → 仕様名 → 仕様番号 → 工程）は、そのままここに入っています。変えたのは、仕様番号の下に「平場・立上り」の段を1つ足したことと、工程が材料を番号で指すことです。価格はここに持ちません。
  • ② 自社データ：客先登録（取引先）・マイ仕様・自社の材料・仕入単価。会社が自分で直す所は全部ここ。参考データを「取り込む」と、写しが自社のものになり、量や材料を直せます。元の仕様と版を覚えているので、カタログが改訂されたときに気づけます。
  • ③ 案件：1つの現場。部位の大きさ（図面から）× 工程の量（マイ仕様から）＝ 材料の必要量。それを容量で割って荷姿の数、単価を掛けて金額。打ち直しが無いことが、この帯の値打ちです。

「商社Aと商社Bで仕入れ値が違う」への答え

  • 材料は1行のままにします。商社ごとに材料の行を増やすと、仕様の工程がどちらを指せばよいか分からなくなり、一覧も倍になります。
  • 値段は「仕入単価」という別の箱に、材料 × 商社で1行ずつ持ちます（商社・単価・いつの値か）。
  • その中の1つに「標準」の印を付けます。見積と概算材料費は標準の単価を使います。
  • 一覧の単価の列には、標準の単価と「2社」のような小さい印だけを出します。押すと商社ごとの値段が並び、標準を付けかえられます。
  • 発注のときは、商社を選ぶと、その商社の単価に切りかわります。標準より安い商社があれば、そこで分かります。
  • 「いつの値か」を持つので、古い単価（たとえば半年以上前）に印を付けられます。値上げの多い今は、これが効きます。

いまのアプリとの差（正直に）

  • もうあるもの：参考データとマイ仕様の分かれ目（仕様登録の3つのタブ）、カタログの材料と登録済み材料の分かれ目、物件 → 屋根 → 部位、図面からの数量、見積書、発注、写真・工程表、請求確認。
  • 形が違うもの：工程と材料は名前の文字で照らしている（番号で指していない）。単価は材料に1つだけ。平場と立上りは別の仕様として並んでいる。取引先の種別は1つ。締め日・支払い条件は物件や企業の側にある。
  • 無いもの：仕入単価（商社ごと）、選べる材料の組を数量に使うこと、確認の状態を付けていく仕組み、実績を仕様の量へ戻す道、会社ごとにデータを分ける置き場（いまは端末の中）。

作る順番の案

  1. 仕入単価（材料 × 商社）。保存の形が「単価1つ」から「単価の並び」に変わるので、古い保存を読める形で入れる。今日の一覧の「その場で単価を入れる」が、そのまま入口になる。
  2. 工程が材料を番号で指す。参考データは道具で作り直せるので、変換の道具（原簿 → アプリ）側で番号を入れる。名前の照らし合わせは、番号が無い古いマイ仕様のためだけに残す。
  3. 平場と立上りを1つの仕様にまとめる。記録帳の部位（平場・立上り）が、同じ仕様番号の別の層を自動で使う。
  4. 確認の状態を原簿とアプリの両方に持ち、確かめた製品から「確認済」にしていく。
  5. 取引先の作り直し（種別を複数・拠点・担当者・取引の条件）。発注書と請求の宛先がここから出るようにする。
  6. 実績を戻す道と、会社ごとの置き場（クラウド）。ここは売り方（何社で使うか）が決まってから。

この図は案です。箱の切り方（とくに「取引の条件」をどこに付けるか、役物の扱い）は、実際の仕事の流れと合っているかを見て直してください。
